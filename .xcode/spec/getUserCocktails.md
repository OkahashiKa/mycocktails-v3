# MyCocktails – ユーザーカクテル表示機能 要件定義

## 概要

ユーザーが登録した「ユーザー材料リスト」を元に、  
**実在するカクテルのみ**を対象とし、  
**作成可能なカクテルの一覧を最大 100 件まで網羅的に取得して表示する機能**を提供する。

/{ユーザー ID}にユーザーが作成可能なカクテルを表示する画面を実装する。
パスパラメータに指定されたユーザー ID に紐づくユーザー材料リストを Supabase から取得し、その後 OpenAI API から作成可能カクテルリストを取得する。

各カクテルには **Wikipedia から引用した画像 URL** を付与して返却する。

AI には OpenAI API の Structured Outputs（JSON Schema）を使用する。

---

## 技術スタック

- OpenAI API

## 1. カクテル選定ルール

### ✔ 実在するカクテルのみを返す

- 創作カクテルは一切生成しない
- Wikipedia にページが存在するカクテルに限定する
- Wikipedia に画像（infobox image）が存在しない場合は除外する

### ✔ ユーザーの手持ち材料で作れるもののみ

- 手持ち材料のみでレシピが成立するカクテルに限定する
- 足りない材料が存在する場合、そのカクテルは返さない

### ✔ 最大 100 件まで

- 作成可能なカクテルを網羅的に抽出する
- 上限を超える場合は一般的な知名度や代表性の高いカクテルを優先
- 最大件数は環境変数で管理し、変更可能とする

---

## 2. Wikipedia 画像取得ポリシー

### ✔ カクテルの画像は Wikipedia の画像 URL を使用

- Wikipedia のカクテルページの main image（infobox の画像）を参照
- 画像が存在しない場合や、取得できなかった場合は images/noimage-760x460.png のダミー画像を使用する

---

## 3. AI プロンプト方針

### システムプロンプト要件

- 実在するカクテルのみ返す
- Wikipedia の画像が存在するもののみ返す
- JSON Schema に strict に従い出力
- 手持ち材料で完全に再現できるカクテルのみ対象
- 最大 100 件まで生成する

### ユーザープロンプト要件

- ユーザーの手持ち材料リストをそのまま渡す
- その材料で作成可能なカクテルを網羅的に抽出
- 足りない材料を必要とするカクテルは除外
- 画像 URL は Wikipedia 由来のもののみ許可

---

## 4. AI の出力形式（JSON Schema 仕様）

### 返却オブジェクト構造

- **total**
  - 返却されるカクテル件数
- **cocktails[]**
  - カクテル情報の一覧

### カクテル情報項目

| フィールド            | 説明                                     |
| --------------------- | ---------------------------------------- |
| id                    | カクテルの一意識別子（英名・スラッグ等） |
| name                  | カクテルの正式名称                       |
| description           | カクテルの簡潔な説明（日本語）           |
| image_url             | Wikipedia の画像 URL（必須）             |
| ingredients[]         | 材料名・分量・ユーザー材料であるかどうか |
| missing_ingredients[] | 材料不一致が無いため基本空配列           |
| difficulty            | easy / normal / hard                     |
| alcohol_level         | low / medium / high                      |
| steps[]               | 作り方手順（日本語）                     |

---

## 5. バリデーション要件

### AI 側

- JSON Schema に strict に従う
- image_url は URI 形式必須
- Wikipedia ドメインのみ許可
- 余計なフィールドは禁止

### アプリ側

- 画像 URL が Wikipedia（`*.wikipedia.org` / `*.wikimedia.org`）かを検証

---

## 6. 非機能要件

### パフォーマンス

- 最大 100 件のカクテルデータを扱えること
- 応答速度とコストの観点から簡潔な説明文を生成する

### コスト最適化

- 画像生成は行わない
- Wikipedia の画像をそのまま引用するため追加コスト無し
